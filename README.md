# Borme Data Pipeline Project

This project implements a complete, automated **ETL data pipeline** to gather information about newly incorporated companies in Spain from the **Official Gazette of the Commercial Registry (BORME)**.

The system is able to crawl the BOE website, download the official bulletins as PDFs, extract the unstructured information (plain text), and transform it into clean, structured data (CSV) ready for analysis.

## Project Structure

The project follows a modular architecture in which an orchestrator (`__main__.py`) coordinates the different specialized modules:

```text
borme-etl-pipeline/
├── assets/
│   └── mappings.json        # Dictionaries to normalize provinces, street types and company types.
├── data/
│   ├── inputs/              # Optional input files.
│   ├── logs/                # Execution logs (error and process history).
│   └── outputs/             # Generated results:
│       ├── urls_borme.txt
│       ├── pdfs_borme/
│       ├── empresas_borme.json
│       └── empresas_constitucion_limpio.csv
├── src/
│   ├── __main__.py          # Entry point (Orchestrator).
│   ├── spider.py            # Link finder.
│   ├── fetcher.py           # File downloader.
│   ├── http_client.py       # Shared HTTP session (timeouts, retries, User-Agent).
│   ├── crawler.py           # Information extractor (PDF -> JSON).
│   └── wrangler.py          # Data cleaner (JSON -> CSV).
├── tests/                   # Unit tests (pytest), no network needed.
│   ├── conftest.py          # Adds src/ to the import path.
│   ├── test_crawler.py      # Company blocks: names, fields, ignored acts.
│   ├── test_spider_fetcher.py # Link extraction, deduplication, skipped and failed downloads.
│   └── test_wrangler.py     # Addresses, capital, dates, provinces, company types.
├── requirements.txt         # External dependencies list.
└── README.md                # Project documentation.
```

## Module Description (`src/`)

### 1. `__main__.py`

The single entry point. Uses `argparse` to manage command-line arguments and `logging` to record activity. Coordinates the calls to the other scripts.

### 2. `spider.py`

Connects to the BOE website for a specific date.

* **Function:** Parses the day's HTML and extracts the provincial PDF URLs.
* **Idempotent append:** Appends new URLs to `data/outputs/urls_borme.txt` and skips the ones already saved, so a day or a whole month can be re-run without creating duplicates.

### 3. `fetcher.py`

Reads the list of URLs generated by the spider.

* **Function:** Downloads the PDFs one by one into `data/outputs/pdfs_borme/`, first checking that the URL file exists. Skips PDFs that are already downloaded and writes each file atomically, so an interrupted run can simply be restarted. Includes pauses to avoid overloading the server.

### 4. `crawler.py`

The text processing engine.

* **Function:** Reads the PDFs using `pypdf`. Detects text blocks corresponding to companies and extracts raw fields (Name, Capital, Address, Date).
* **Output:** Generates a raw JSON file (`empresas_borme.json`) with Incorporations, Dissolutions and other acts.

### 5. `wrangler.py`

The data refiner.

* **Filter:** Selects only **"Incorporation"** ("Constitución") acts.
* **Cleaning:** Normalizes dates (DD-MM-YYYY) and monetary values (float).
* **Address Algorithm:** Uses advanced **Regular Expressions (Regex)** with 5 priority strategies to parse complex addresses (street type, name, number, city), handling cases without commas, with kilometer markers, blocks, etc.
* **Output:** Generates the final deliverable: `empresas_constitucion_limpio.csv`.

### 6. `http_client.py`

Shared HTTP configuration used by the spider and the fetcher.

* **Single session:** Both modules reuse one `requests` session, which keeps the connection open between requests to the same server.
* **Timeouts:** Every request has a connect and read timeout, so a server that stops responding cannot hang the pipeline.
* **Retries:** Temporary server errors (429 and 5xx) are retried up to three times with exponential backoff, honouring the `Retry-After` header.
* **User-Agent:** A browser User-Agent defined in a single place, so it is not duplicated across modules.

## Libraries and Dependencies

### Why is `requirements.txt` so short?

The `requirements.txt` file only contains:

* `requests`
* `beautifulsoup4`
* `pypdf`

### Where are `json`, `csv`, `os`, `re` or `time`?

They don't need to be installed — they are already part of Python's Standard Library.

## Installation

This project requires **Python 3.x**.

1. **Create a virtual environment:**
```bash
python3 -m venv venv
source venv/bin/activate
```


2. **Install external dependencies:**
```bash
pip install -r requirements.txt
```


## Execution Guide

To meet the goal of gathering companies incorporated in **September 2025**, follow these exact steps from the project's root folder:

### STEP 1: Spider (Collect URLs for the whole month)

We run a loop to crawl from day 1 to day 30. Re-running it is safe: URLs already saved are not duplicated.

```bash
for i in {01..30}; do python3 src/__main__.py -p spider -d 202509$i; done
```

### STEP 2: Fetcher (Download the PDFs)

We download all the documents collected in the previous step.

```bash
python3 src/__main__.py -p fetcher
```

### STEP 3: Crawler (Generate the JSON)

We read the PDFs and generate the intermediate structured file.

```bash
python3 src/__main__.py -p crawler
```

### STEP 4: Wrangler (Generate the Final CSV)

We clean the data and generate the final filtered file.

```bash
python3 src/__main__.py -p wrangler
```

## Tests

The parsing logic (names, addresses, capital, dates, provinces) and the re-run behaviour of the spider and fetcher are covered by unit tests. They use small text samples and a fake HTTP session, so they run in under a second without network access.

```bash
python3 -m pytest
```

## Logs and Results

* **Results:** The final file will be at `data/outputs/empresas_constitucion_limpio.csv`.
* **Logs:** You can check the execution history and possible errors in the `data/logs/` folder, where a daily file based on the run date will be generated (`pipeline_YYYYMMDD.log`).
* **Exit code:** Each phase exits with code `0` on success and `1` if any step failed (missing input, failed download, unreadable PDF...), so loops, cron jobs or an orchestrator can detect failures.
